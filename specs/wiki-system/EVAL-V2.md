# Evaluation set v2 (Phase E, gate G0)

Status: builder implemented 2026-11-15; corpus not yet frozen. See [DECISIONS.md](DECISIONS.md) D2 (thresholds) and D5 (source and confidentiality).

## Confidentiality

The only real source is the Pi LLM Wiki (`~/.pi/agent/llm-wiki/wiki`). The following stay in ignored `.cache/eval/v2/` and go only to the local approved endpoint:
- page text;
- generated questions, answers and labels;
- every model response.

`research/eval-corpus/frozen/v2/manifest.json` is the only committed artifact. It holds hashes, counts, seed, prompt hashes and model identity. Builder logs and test output print counts only.

## Source facts (aggregate scan, 2026-11-15)

- **Size:** 2,009 pages: 1,786 `source`, 108 `entity`, 78 `concept`, 22 `analysis`, 5 `synthesis`, 2 `skill`.
- **Page shape:** median 1.3 KB and 27 lines. 1,505 pages have no wikilinks.
- **Duplication:** no exact duplicates after normalization, and median boilerplate share is 3%.
- **No Ukrainian text:** the Ukrainian slice is Ukrainian questions against English pages.
- **No current/superseded state:** `status` is `observation`, `insight` and similar, so the superseded slice is synthetic.

## Slices

All questions are generated by `qwen3.8-35b-a3b-mtp-32k` (temperature 0, seed fixed, thinking off) and accepted only if code-level validators pass. The model never decides the gold labels on its own; ambiguous items go to the owner.

| Slice | Positives | How it is built | Validator |
|---|---|---|---|
| identifier_exact | 40 | Question built around an identifier token that occurs in exactly one page | token in question; token unique to gold page |
| paraphrase | 50 | Question answerable from one quoted span, in different words | span verbatim in page; question/page content-word overlap ≤ 0.4 |
| cross_language_ukrainian | 50 | Same, question in Ukrainian | span verbatim; ≥ 60% Cyrillic letters in question |
| multi_page | 50 | Question needing one span from each of two related pages (wikilink, else shared tag) | each span in its own page; neither page holds both |
| superseded_decision | 50 | Model proposes one fact change (old → new span); the changed body is published as a newer revision | old span occurs once; new ≠ old; gold = current revision; answer must use new value |
| cross_project_lookalike | 50 | Copy of a page with an altered fact under the same page id in project `lookalike`; question asked in the main project | as superseded; any `lookalike` citation is a disclosure |
| child_written_fact | 50 | New note page written as a child agent's output (actor `child`), adding a decision sentence absent from every original page | sentence absent from the original corpus; gold = child page |
| missing_control | 30 | Plausible question about a real page's subject whose answer is absent | **every item owner-labeled** |
| conflict_control | 20 | Second active page (different id) contradicting a real fact | **every item owner-labeled**; expected abstention = conflicting |

That makes 340 positives and 50 controls. With the 60% holdout, every hard slice keeps ≥ 30 held-out positives.

## Ambiguity and labeling

The labeling queue holds every control, plus any positive whose answer span also occurs verbatim in another page (more than one candidate gold), capped at about 100 items. `labeling.html` is written to `.cache/eval/v2/` and opened locally. The owner's answers are saved as a JSON download and placed at `.cache/eval/v2/labels.json`. Items the owner rejects are dropped before splitting; quotas are refilled from the next candidates and re-labeled if needed.

## Split and freeze

- **Split:** within each slice, questions are ordered by `sha256(seed || question id)`; the first 40% go to development, the rest to held-out.
- **Freeze:** writes the manifest, with SHA-256 of every data file, the prompt texts' hashes, the generator model id and the D2 thresholds. The manifest is committed before any v2 measurement. Tuning uses development items only.
- **Authority loading:**
  - real pages are created by `owner`;
  - superseded revisions and lookalike/conflict pages are published through the normal propose → decide path;
  - child pages are proposed by principal `child`.

### Hybrid answers and semantic review

With the approved embedding model and retrieval profile configured, use
`python3 src/eval/measure_v2.py --subset holdout --answers` to run hybrid recall
and collect answers from the approved loopback endpoint. Keep raw responses,
retrieved passages and review labels under the private run directory
`.cache/eval/v2/runs/<run-id>/`.

For separate retrieval and answer runs, omit `--answers` and run
`python3 src/eval/answer_v2.py <run-id> --resume --request-timeout-seconds 180`
against the saved retrieval run. Reuse the same deadline when resuming a
checkpoint. The collector verifies the checkout, retrieval inputs and completed
rows before contacting the model. Its default per-request deadline is 150 seconds.

An independent reviewer must compare each positive answer that has valid
citations against the frozen question and required facts. Check that it
answers in the requested language, covers every required fact and that its
cited passages support every claim. In `answer-labels.json`, key each verdict
by the question id and record its `sha256` from `answers.jsonl` and a Boolean
`correct_supported`. Review against the frozen gold evidence and the passages
actually supplied to the model. The score rejects a verdict for a changed
answer or changed evidence.

Run `python3 src/eval/answer_v2.py <run-id>` for the aggregate answer report.
Missing reviews, malformed answers and invalid citations fail the report.
Any direct answer on a negative or conflicting control counts as a confident
answer. Holdout runs using the pinned D14 retrieval profile write separate
recall and answer receipts. Answer receipts require completed review and the
original checkout identity. Only receipts from a clean release candidate
count toward gate acceptance.

### Saved generations

Development trace reuse (`python3 src/eval/trace_v2.py --reuse-from <run-id>`)
and the performance command below require write access to the saved run's
`indexes/` project directories. The copier takes the generation lock and
creates a temporary lease that live cleanup honors until the copy finishes.
Use a writable source run if the saved run is on a read-only mount.

### Concurrent performance

After the answer endpoint is idle, run
`WIKI_TEST_CACHED_MODEL=<embedding-path> WIKI_EVAL_RERANKER=<reranker-path> python3 src/eval/measure_perf_v2.py <run-id>`.
This measures 100 warm recalls across ten readers and one overlapping batch of
ten synthetic publications against a disposable clone of the holdout index.
It verifies every published revision through current hybrid recall, reports the
coverage seen during rebuild, and writes a separate G2 performance receipt.
